# PHASE 8B — STRIPE SECURITY AUDIT & SPECIFICATION

## 1. Zero Client Secret Exposure Policy
- **Frontend (`VITE_` variables)**: Only `VITE_STRIPE_PUBLISHABLE_KEY` is permitted in the client-side bundle.
- **Server Variables**: `STRIPE_SECRET_KEY` (`sk_...`) and `STRIPE_WEBHOOK_SECRET` (`whsec_...`) are strictly loaded server-side and never imported into React components.
- **Verification Evidence**: Ripgrep scans of the `dist/` directory confirmed 0 occurrences of secret keys or signatures.

## 2. Server-Side Identity Verification
- When creating Checkout or Customer Portal sessions, the server derives user identity directly from Supabase Authentication (`auth.uid()`).
- Arbitrary `customer_id` or `stripe_price_id` parameters sent from browser clients are rejected.
- Portal sessions for User A cannot be accessed or generated by User B.

## 3. Webhook Signature Verification
- Webhook payloads are received with raw body buffers and cryptographically validated using HMAC-SHA256 via `stripe.webhooks.constructEvent`.
- Unauthorized or forged webhooks are rejected with HTTP 400.

## 4. Idempotency & Database Integrity
- `billing_webhook_events.provider_event_id` enforces unique delivery.
- `billing_customers(user_id, provider)` enforces 1:1 customer mapping.
- `subscriptions(provider_subscription_id)` guarantees one authoritative subscription row per Stripe subscription.
